# target-price-tracker

분기 실적표(매출, 영업이익)만으로 **증분 영업이익률**을 계산해서 이익률
추세가 꺾이는 시점을 전체 평균보다 먼저 잡아내는 도구.

## 증분 영업이익률이란

전체 이익률("10% → 20%로 개선")이 아니라, 늘어난 매출과 늘어난 영업이익만
따로 떼어내서 계산한다.

|        | 매출  | 영업이익 | 전체 이익률 |
|--------|------|--------|-----------|
| 이전 분기 | 100조 | 10조   | 10%       |
| 이번 분기 | 150조 | 30조   | 20%       |

- 증가한 매출 = 50조, 증가한 영업이익 = 20조
- **증분 영업이익률 = 20 ÷ 50 = 40%**

기존 매출은 10%짜리지만 새로 붙는 매출은 40%짜리("10, 40, 40").
이 증분 이익률이 계속 올라가는 회사가 이익 성장이 폭발하는 회사다.

## 왜 이렇게 보는가: 평균보다 먼저 움직인다

전체 이익률 m과 증분 이익률 m_inc 사이에는 다음 관계가 성립한다:

```
Δm = (ΔR / R_new) × (m_inc − m_old)
```

전체 이익률의 기울기는 **(증분 − 전체) 격차에 비례**한다. 그래서:

- m_inc > m 인 동안은 증분이 이미 하락 중이어도 전체 이익률은 계속 오른다
  (평균은 둔하게 움직여서 신호가 늦다).
- **m_inc가 m을 하향 돌파하는 순간이 전체 이익률의 고점.**
- 증분 이익률 정체 = 가격 인상(P)이 실적에 다 반영됐다는 신호.
  이때부터는 물량(Q)이 늘어야만 성장이 가능하다.

함께 계산하는 것:

- **손익분기 매출("빵원 되는 자리")**: 분기 실적을 직선 적합해서 영업이익이
  0이 되는 매출 수준을 추정. 판관비(고정비) 축소로 이 자리가 낮아지고
  플러스로 돌아서는 시점부터 주가가 크게 오른다.
- **급등 감지**: 증분 이익률이 갑자기 튀면 사업보고서에서 원인을 찾을 것.
  신사업·독점 등이면 강한 매수 시그널.
- **당기순이익은 쓰지 않는다.** 주식평가이익, 전환사채 평가 같은 게 섞여서
  의미가 없다. 오직 매출과 영업이익만 입력받는다.

## 자동화: 종목명 하나로 끝내기 (DART API)

```bash
# 1) 최초 1회: https://opendart.fss.or.kr 에서 무료 인증키 발급 후
export DART_API_KEY=발급받은키        # 또는 dart_api_key.txt 파일로 저장

# 2) 종목명(또는 종목코드)만 주면: 다트에서 분기 매출액·영업이익 수집
#    → watchlist/효성중공업.csv 저장 → 주가까지 붙여 리포트 생성
python dart_fetch.py 효성중공업 --from 2022 --build watch.html

# 종목 추가는 같은 명령 반복 (파일이 쌓이고 --build가 전체를 다시 그림)
python dart_fetch.py 005930 --from 2022 --build watch.html
```

분기 값은 보고서 누적치 차분으로 도출한다(Q4 = 사업보고서 − 3분기 누적
등 — DART 손익 계정의 누적 혼선을 피하는 표준 방식). 연결(CFS) 우선,
`--ofs`로 별도 재무제표 선택. 금액은 백만원으로 환산 저장. 컨센서스(E)는
DART에 없으므로 리포트의 붙여넣기 박스(FnGuide, ×100 변환)나 표 편집으로
추가한다.

## 다트 재무 데이터 수집기 (버튼으로 수집/업데이트)

```bash
python3 dart_app.py     # http://127.0.0.1:8899 브라우저 자동 오픈
```

로컬 미니 앱이 뜬다. 종목명을 입력하고 **[종목 추가]**를 누르면 최근
3년 + 올해 진행분의 **매출액·영업이익·판관비·재고자산**을 다트 전체
재무제표 API에서 수집해 `data/` 폴더에 종목별 JSON으로 보관한다
(연간/분기 분리, 단위 백만원). 새 분기·반기·사업보고서가 공시되면
**[업데이트]** 버튼 — 작년~올해 보고서를 다시 받아 새 분기만 병합한다
(몇 번을 눌러도 안전한 멱등 동작). 화면에서 분기별/연간 탭으로
영업이익률·판관비율·재고/매출 비율까지 확인.

손익 항목은 보고서 누적치의 분기 차분, 재고자산은 분기말 잔액.
연결(CFS) 우선, 없으면 별도(OFS). watch.html(증분 이익률 리포트)과는
독립적으로 동작한다.

## 사용법 (수동 입력)

```bash
# 터미널 테이블 출력
python incremental_margin.py examples/sample_quarters.csv

# 이익률·증분이익률·주가를 한눈에 비교하는 HTML 리포트 (테이블 + 차트)
python incremental_margin.py examples/sample_quarters.csv --html report.html

# FnGuide Financial Highlight 화면을 복사해 파일로 저장하거나 그대로 붙여넣기
python incremental_margin.py examples/sample_paste.txt --html report.html --title "종목명"
python incremental_margin.py - --html report.html   # 붙여넣고 Ctrl-D

# 종목코드로 일별 종가 시계열을 받아 주가 선그래프 표시 (네이버 금융, 키 불필요)
python incremental_margin.py examples/sample_paste.txt --fetch-price 298040 --html report.html

# API 대신 일별 시세 CSV(날짜,종가) 사용
python incremental_margin.py examples/sample_paste.txt --price-csv daily.csv --html report.html

# 워치리스트: 종목 파일 여러 개 → 하나의 HTML (파일 하나 = 종목 하나)
python watchlist.py examples/watchlist --fetch-price --html watch.html
```

## 워치리스트 (종목 n개 추적)

`watchlist.py`는 디렉토리(또는 파일 목록)를 받아 **워치리스트 → 종목
상세** 2뎁스 리포트 하나를 만든다. 종목명은 파일명, 파일 안에
`#code=298040` 주석을 넣으면 `--fetch-price` 플래그로 일별 시세가
자동으로 붙는다. 예: `examples/watchlist/`.

리포트 안에서 되는 것:

- 상단 워치리스트 테이블: 종목별 최신 분기·전체/증분 이익률·격차·추세·
  최근 종가 요약, 행 클릭으로 종목 전환
- **`+ 종목 추가` / 현재 종목 삭제** — 브라우저에서 바로. 새 종목은
  FnGuide 표를 붙여넣기 박스에 넣으면 분기가 채워진다(주가는 CLI로
  재생성해야 붙음)
- **종목명 수정**: 상세 화면의 제목을 클릭해 바로 수정
- 모든 편집은 localStorage에 저장. **리포트를 재생성해 열면 임베드
  데이터가 바뀐 종목은 새 데이터로 교체된다**(재생성이 데이터 원본).
  임베드가 그대로인 종목만 브라우저 수정본이 유지된다

입력 형식은 자동 감지되며 두 가지를 받는다. **기간 제한 없음** —
붙여넣는 만큼(다트에서 긁은 과거 분기 포함) 전부 그려진다.

분기 라벨은 `2024.3분기` 형식으로 표준화된다 — `2024/09`, `24.3분기`,
`2024Q3`으로 입력해도 자동 변환된다.

1. **세로형 CSV**: 헤더 `quarter,revenue,operating_profit[,price]`
   (또는 `분기,매출,영업이익[,주가]`)
2. **가로형 붙여넣기** (FnGuide 등): 헤더 줄에 `2025/03 2025/06 ...
   2026/06(E)` 식 분기 라벨, 아래에 `매출액` / `영업이익` /
   `영업이익(발표기준)` / `주가` 행. 탭·공백 구분 모두 허용, `영업이익`
   행의 빈 칸은 `영업이익(발표기준)` 행 값으로 채운다.

금액 단위는 **백만원**을 기준으로 표기한다(다트 사업보고서 기준).
FnGuide Financial Highlight는 억원 단위이므로 리포트의 붙여넣기 박스에서
"억원 ×100 변환" 체크를 켜면 백만원으로 통일된다. 예제 데이터도 전부
백만원 단위다.

`(E)` 분기는 **컨센서스 추정치**로 취급한다: 차트에 점선·빈 마커·배경
워시로 구분되어 표시되고, 추세 판정·KPI·손익분기 계산에서는 제외된다.
대신 "컨센서스가 반영하는 증분 이익률" 시그널로 최근 실적 증분과
비교해준다 — 시장이 앞으로 붙는 매출을 몇 %짜리로 보고 있는지.

주가 열은 선택 — 있으면 주가 패널이 함께 그려진다. `--fetch-price
종목코드`를 주면 네이버 금융에서 실적 분기의 분기말 종가를 자동으로
받아 채운다(추정 분기 제외). 금액 단위는 자유 — 일관되기만 하면 된다.

HTML 리포트 구성:

- x축은 **날짜(시간) 축**: 분기 지표는 분기 말일 위치에 찍힌다
- KPI 타일: 최신 전체 이익률, 증분 이익률, 증분−전체 격차, 손익분기 매출,
  최근 종가(직전 분기말 대비 등락)
- 주가 그래프는 없음(오버레이 포함 제거). 주가 시계열이 주입돼 있으면
  KPI의 '최근 종가' 타일에만 표시
- 매출이 줄어든 분기의 증분값은 부호가 반전된 노이즈라 차트에서 제외 —
  그 자리에서 선이 끊기고 전후의 유효한 값은 점으로 표시된다(값은
  표·툴팁에서 확인, 추세 판정 제외)
- **증분 전년 동기(YoY) 기준 토글**: 계절성 종목(분기마다 매출이
  오르내리는)은 QoQ 증분이 지저분하다 — YoY로 켜면 4분기 전과 비교해
  계절성과 부호 반전 노이즈가 사라진다. 표의 Δ·증분 컬럼, KPI, 추세
  판정, 워치리스트 요약이 함께 전환된다
- **분기 실적표 직접 편집**: `+ 과거 분기`(표 맨 위에 이전 분기 —
  다트에서 긁은 옛 실적 입력용), `+ 최신 분기`(맨 아래에 다음 분기),
  행 삭제, 매출·영업이익 수정, 컨센서스(E) 체크 — 바꾸는 즉시
  차트·KPI·시그널이 재계산된다. 분기 라벨은 자동 제안(2025/03 앞은
  2024/12). 수정 내용은 브라우저에 자동 저장(localStorage), `초기화`로
  생성 시점 데이터 복귀. 주가는 표에서 입력하지 않는다 — `--fetch-price`
  또는 `--price-csv`로 일별 시계열이 심어진다
- 마우스 크로스헤어: 거래일에 스냅되어 날짜·주가와 해당 분기의 전체·증분
  이익률을 툴팁 하나로 표시 (키보드 ←/→로 분기 이동)
- 시그널 목록: 추세·격차·손익분기·컨센서스 비교
- 라이트/다크 모드 자동 대응, 외부 의존성 없는 단일 HTML 파일
- 분기 라벨이 날짜로 해석되지 않으면(2025/03·2025Q1 형식이 아니면)
  등간격 x축으로 폴백하고 주가 차트는 표시하지 않는다

리포트의 계산 로직은 `incremental_margin.py`(터미널 출력)와 템플릿 안의
JS(편집 시 재계산)에 같은 규칙으로 두 벌 존재한다 — 임계값·판정 규칙을
바꿀 때 양쪽을 함께 고칠 것.

### 주의점

- QoQ 단일 차분은 노이즈에 취약하다. 계절성(4분기 성과급 등)·일회성 항목이
  있는 업종이면 전년 동기(YoY) 기준이나 4분기 롤링 합산으로 넣는 게 안정적.
- 매출이 거의 안 변한 분기의 증분 이익률은 분모가 작아 의미가 없다
  (매출 변화 0이면 `-`로 표시).
- 매출 감소 구간은 부호가 뒤집히므로 추세 판정에서 제외한다.
